# Онлайн-магазин электроники — проектирование базы данных

## Дорожная карта проекта

### Цель проекта

Разработать структуру базы данных для онлайн-магазина электроники, обеспечивающую:

- управление каталогом товаров;
- хранение информации о категориях;
- регистрацию покупателей;
- оформление и сопровождение заказов;
- учет состава заказов и приобретенных товаров.

# 1. Выбор сценария

Для реализации проекта выбран сценарий **«Онлайн-магазин электроники»**.

Система предназначена для автоматизации основных бизнес-процессов интернет-магазина:

- каталогизация товаров;
- управление категориями;
- регистрация покупателей;
- оформление заказов;
- хранение состава заказов;
- расчет стоимости покупки.

# 2. Архитектура базы данных

База данных состоит из пяти основных сущностей:

| Сущность | Назначение |
|----------|------------|
| Categories | Категории товаров |
| Products | Каталог товаров |
| Customers | Покупатели |
| Orders | Заказы |
| OrderItems | Состав заказа |

---

# 3. Сущности и атрибуты

## Categories

Используется для группировки товаров по категориям (например: смартфоны, ноутбуки, аксессуары).

**Основные атрибуты:**

- идентификатор категории;
- название категории;
- описание.

## Products

Хранит информацию о товарах.

**Основные атрибуты:**

- название товара;
- цена;
- количество на складе;
- категория.

## Customers

Содержит информацию о зарегистрированных покупателях.

**Основные атрибуты:**

- имя;
- фамилия;
- email;
- телефон;
- дата регистрации.

## Orders

Представляет оформленные заказы покупателей.

**Основные атрибуты:**

- покупатель;
- дата заказа;
- статус;
- итоговая сумма.

## OrderItems

Связывает товары и заказы, реализуя отношение **многие-ко-многим**.

**Основные атрибуты:**

- заказ;
- товар;
- количество;
- цена товара на момент покупки.

# 4. Проектирование таблиц

## Таблица Categories

**Описание:** хранит категории товаров.

| Поле | Тип | Ограничения |
|------|-----|-------------|
| category_id | INTEGER | PK, NOT NULL |
| category_name | VARCHAR(100) | NOT NULL, UNIQUE |
| description | TEXT | NULL |

### Ограничения

- PRIMARY KEY (category_id)
- UNIQUE (category_name)

---

## Таблица Products

**Описание:** каталог товаров магазина.

| Поле | Тип | Ограничения |
|------|-----|-------------|
| product_id | INTEGER | PK, NOT NULL |
| product_name | VARCHAR(255) | NOT NULL |
| price | NUMERIC(10,2) | NOT NULL |
| stock_quantity | INTEGER | NOT NULL DEFAULT 0 |
| category_id | INTEGER | FK |

### Ограничения

- PRIMARY KEY (product_id)
- FOREIGN KEY (category_id) REFERENCES Categories(category_id)
- CHECK (price >= 0)
- CHECK (stock_quantity >= 0)

---

## Таблица Customers

**Описание:** данные покупателей.

| Поле | Тип | Ограничения |
|------|-----|-------------|
| customer_id | INTEGER | PK, NOT NULL |
| first_name | VARCHAR(100) | NOT NULL |
| last_name | VARCHAR(100) | NOT NULL |
| email | VARCHAR(255) | NOT NULL, UNIQUE |
| phone | VARCHAR(20) | NULL |
| created_at | TIMESTAMP | NOT NULL DEFAULT CURRENT_TIMESTAMP |

### Ограничения

- PRIMARY KEY (customer_id)
- UNIQUE (email)

---

## Таблица Orders

**Описание:** информация о заказах.

| Поле | Тип | Ограничения |
|------|-----|-------------|
| order_id | INTEGER | PK, NOT NULL |
| customer_id | INTEGER | FK |
| order_date | TIMESTAMP | NOT NULL DEFAULT CURRENT_TIMESTAMP |
| status | VARCHAR(50) | NOT NULL DEFAULT 'Pending' |
| total_amount | NUMERIC(10,2) | NOT NULL DEFAULT 0.00 |

### Ограничения

- PRIMARY KEY (order_id)
- FOREIGN KEY (customer_id) REFERENCES Customers(customer_id)
- CHECK (status IN ('Pending', 'Processing', 'Shipped', 'Delivered', 'Cancelled'))
- CHECK (total_amount >= 0)

---

## Таблица OrderItems

**Описание:** состав заказа.

| Поле | Тип | Ограничения |
|------|-----|-------------|
| order_item_id | INTEGER | PK, NOT NULL |
| order_id | INTEGER | FK |
| product_id | INTEGER | FK |
| quantity | INTEGER | NOT NULL |
| unit_price | NUMERIC(10,2) | NOT NULL |

### Ограничения

- PRIMARY KEY (order_item_id)
- FOREIGN KEY (order_id) REFERENCES Orders(order_id) ON DELETE CASCADE
- FOREIGN KEY (product_id) REFERENCES Products(product_id)
- CHECK (quantity > 0)
- CHECK (unit_price >= 0)
- UNIQUE (order_id, product_id)

# 5. Взаимосвязи между таблицами

## Categories → Products

**Связь:** один ко многим (1:N)

Одна категория может содержать множество товаров.

```text
Categories
    |
    | 1
    |
    |——— N
Products
```

Внешний ключ:

- Products.category_id → Categories.category_id

---

## Customers → Orders

**Связь:** один ко многим (1:N)

Один покупатель может оформить несколько заказов.

```text
Customers
    |
    | 1
    |
    |——— N
Orders
```

Внешний ключ:

- Orders.customer_id → Customers.customer_id

---

## Orders → OrderItems

**Связь:** один ко многим (1:N)

Один заказ содержит множество позиций.

```text
Orders
   |
   | 1
   |
   |——— N
OrderItems
```

Внешний ключ:

- OrderItems.order_id → Orders.order_id

---

## Products → OrderItems

**Связь:** один ко многим (1:N)

Один товар может встречаться в составе разных заказов.

```text
Products
    |
    | 1
    |
    |——— N
OrderItems
```

Внешний ключ:

- OrderItems.product_id → Products.product_id

---

# Итоговая логическая модель

```text
Categories
    |
    | 1
    |
    |——— N
Products
    |
    | 1
    |
    |——— N
OrderItems
    |
    | N
    |
    |——— 1
Orders
    |
    | N
    |
    |——— 1
Customers
```

---

# 6. ER-диаграмма

ER-диаграмма включает следующие связи:

- Categories (1) → (N) Products
- Customers (1) → (N) Orders
- Orders (1) → (N) OrderItems
- Products (1) → (N) OrderItems

Сущность **OrderItems** реализует связь **многие-ко-многим** между заказами и товарами и хранит состав каждого заказа.
